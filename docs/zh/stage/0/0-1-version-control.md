# 为什么需要版本控制

## 本课目标

- 理解版本控制系统（VCS）解决什么问题
- 对比集中式与分布式版本控制
- 知道 Git 属于哪一种

## 没有版本控制的痛苦

想象你在写一个项目：改到一半发现方案行不通，想回到昨天下午的状态——昨天下午的文件在哪？可能躺在 `final_v2_备份` 里，也可能早被覆盖了。多人协作更糟：两个人同时改同一个文件，谁后保存谁说了算，另一个人的改动悄无声息地消失。

这三个问题——**记录、回退、协作**——就是 Git 要解决的事。

## 什么是版本控制

版本控制系统（Version Control System，VCS）记录每一次修改，保存项目在某个时刻的完整**快照（snapshot）**，让你可以：

- 查看任意历史版本
- 对比任意两次修改之间的差异
- 随时回退到某个历史版本

它不是备份工具：备份只保留最新一份，而 VCS 保留整条历史，并且每个版本都可重建。

## 集中式与分布式

- **集中式（如 SVN）**：只有一个中央仓库，所有人从它检出代码，提交必须联网发送到服务器。服务器一旦宕机，所有人都无法提交。
- **分布式（如 Git）**：每个 clone 都是中央仓库的完整副本，提交在本地完成，离线也能工作；之后再把提交推送给别人。

Git 的每次 commit 保存的是完整快照而非差异，因此整条历史在任何一份克隆里都完整可重建——这正是「分布式」能够成立的前提。

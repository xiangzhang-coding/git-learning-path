# 术语表

术语一律保留英文原文，本表给出中文释义与首次出现的课。

| 术语 | 含义 | 首现 |
| --- | --- | --- |
| repository | 存储项目历史与元数据的目录（含 `.git`） | 0-2 |
| working tree | 工作区，你正在编辑文件的地方 | 0-2 |
| staging area | 暂存区（也叫 index），待提交改动的清单 | 0-2 |
| commit | 提交，一次完整的快照记录 | 0-1 |
| snapshot | 快照，某一时刻项目全部文件的完整状态 | 0-1 |
| SHA-1 | 内容哈希，commit 的唯一标识 | 阶段 1 |
| HEAD | 指向当前分支最新提交的指针 | 阶段 2 |
| branch | 分支，可移动的提交指针 | 阶段 2 |
| tag | 标签，固定指向某个提交的名字 | 阶段 4 |
| remote | 远程仓库，托管在别处的仓库副本 | 阶段 3 |
| origin | 克隆仓库时默认的远程名 | 阶段 3 |
| clone | 克隆，复制远程仓库到本地 | 阶段 3 |
| fetch | 拉取，下载远程提交但不合并 | 阶段 3 |
| push | 推送，上传本地提交到远程 | 阶段 3 |
| pull | 拉取，等于 fetch + merge | 阶段 3 |
| merge | 合并，把另一条分支并入当前分支 | 阶段 2 |
| rebase | 变基，把提交重新接到新的基线上 | 阶段 4 |
| conflict | 冲突，双方改动重叠需手动解决 | 阶段 2 |
| stash | 贮藏，把未提交改动暂存起来 | 阶段 4 |
| checkout | 检出，切换分支或恢复文件 | 阶段 2 |
| switch | 切换分支（较新的命令） | 阶段 2 |
| restore | 恢复文件到某个版本 | 阶段 1 |
| reset | 重置，移动 HEAD 与暂存区/工作区 | 阶段 4 |
| revert | 回滚，用一条新提交撤销旧提交 | 阶段 4 |
| cherry-pick | 把某个提交复制到当前分支 | 阶段 4 |
| diff | 差异，两次状态之间的改动 | 阶段 1 |
| status | 状态，三个区域间差异的概览 | 阶段 1 |
| log | 日志，提交历史列表 | 阶段 1 |
| tracking branch | 追踪分支，关联到远程分支的本地分支 | 阶段 3 |
| upstream | 上游，本地分支对应的远程分支 | 阶段 3 |
| fast-forward | 快进，没有分叉时的直接前移合并 | 阶段 2 |
| detached HEAD | 游离 HEAD，HEAD 不指向任何分支 | 阶段 4 |
| reflog | 引用日志，HEAD 移动的完整记录 | 阶段 4 |
| DAG | 有向无环图，提交历史的拓扑结构 | 阶段 2 |
| fork | 派生，把别人的仓库复制到自己账号 | 阶段 5 |
| pull request | 拉取请求（PR），请求合入你的分支 | 阶段 5 |
| issue | 问题，仓库里围绕 bug/功能/任务的讨论线程 | 阶段 5 |
| label | 标签，给 issue 分类（如 bug、enhancement） | 阶段 5 |
| milestone | 里程碑，把一组 issue 归入同一版本目标 | 阶段 5 |
| release | 发布，基于 tag 的正式版本，附说明与产物 | 阶段 5 |
| workflow | 工作流，GitHub Actions 的自动化流程 | 阶段 5 |

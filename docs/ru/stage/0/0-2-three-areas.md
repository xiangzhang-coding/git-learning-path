# Модель трёх областей

## Цели урока

- Познакомиться с working tree, staging area и repository
- Понять, что перемещают git add и git commit
- Узнать, что показывает git status

## Три области

Git делит репозиторий на три области:

- **Working tree**: файлы, которые вы редактируете — именно их меняет ваш редактор
- **Staging area (также index)**: список изменений, отобранных для следующего коммита
- **Repository (директория `.git`)**: закоммиченные снимки истории

`git status` показывает ровно различия между этими областями: файлы изменены, но не добавлены; добавлены, но не закоммичены.

## Зачем дополнительная область

Staging area позволяет **коммитить частями**: изменили две несвязанные функции — добавьте и закоммитьте сначала первую, затем вторую. Каждый коммит в истории остаётся чистым, читаемым и откатываемым. Без неё сеанс правок превращается в один мусорный коммит («поправил всякое»).

## Анимация: три области

Нажимайте кнопки и наблюдайте, как файл перемещается между областями: правка происходит в working tree, `git add` регистрирует его в staging area, а историю пишет только `git commit`.

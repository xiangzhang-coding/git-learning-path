# Разрешение merge conflict

## Цели урока

- Понимать причины возникновения конфликта
- Читать маркеры конфликта
- Владеть стандартным порядком разрешения конфликта: редактирование → add → commit

## Как возникает конфликт

При слиянии git сводит изменения обеих сторон воедино. Если стороны меняли **разные места**, git объединяет их автоматически; но если **обе стороны изменили одно и то же место одного файла**, git не может решить, чью версию сохранить, — он помещает в файл обе версии и передаёт решение вам.

```
<<<<<<< HEAD
hello main
=======
hello feature
>>>>>>> feature
```

В выводе git явно укажет, в каком файле конфликт:

```
CONFLICT (content): Merge conflict in hello.txt
Automatic merge failed; fix conflicts and then commit the result.
```

## Маркеры конфликта

Каждый блок конфликта в файле окружён тремя маркерами:

| Маркер | Значение |
| --- | --- |
| `<<<<<<< HEAD` | Ниже — содержимое вашей стороны (текущей ветки) |
| `=======` | Разделитель |
| `>>>>>>> feature` | Ниже — содержимое ветки другой стороны (feature); в маркере — её имя |

**Ваша задача**: решить, что останется (или написать новый вариант), и удалить все три маркера.

## Порядок разрешения конфликта

Стандартный порядок из четырёх шагов:

```bash
git merge feature          # 1. вызвать конфликт
# отредактировать файл: выбрать содержимое, удалить маркеры
git add hello.txt          # 2. сказать git, что файл разрешён
git commit -m "merge: resolve"   # 3. завершить слияние, создав merge commit
```

В это время `git status` напоминает, что идёт слияние: пока есть неразрешённые файлы, показывается `You have unmerged paths`; после add всех файлов — `All conflicts fixed but you are still merging` — тогда можно коммитить.

**Важно**: конфликт — это не ошибка, а передача git права решения вам. После разрешения получится обычный merge commit, и история запишет слияние как обычно.

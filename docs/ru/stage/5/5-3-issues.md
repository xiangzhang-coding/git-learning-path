# Issues и совместная работа

## Цели урока

- Понять, что такое issue и как его открыть
- Организовать задачи с помощью label и milestone
- Связать PR и issue через «fixes #номер»

## Что такое issue

Issue — это ветка обсуждения в репозитории: сообщить о баге, предложить фичу, обсудить конкретную задачу. У каждого issue есть номер (например, #12), заголовок, описание и комментарии, а ещё можно назначить ответственного, повесить label и добавить в milestone.

## Открытие issue

На странице репозитория: Issues → New issue. Хорошее описание содержит: в чём проблема, как воспроизвести, ожидаемое поведение. Во многих репозиториях есть шаблоны issue (отчёт о баге / запрос фичи) — заполнение по шаблону заметно ускоряет обработку.

## Label и milestone

- **label**: классификация issue, например bug, enhancement, good first issue. Фильтр по label — главный способ мейнтейнера наводить порядок.
- **milestone**: объединяет группу issues под цель одной версии, например v1.2.0. Milestone показывает прогресс (выполнено x/y issues).

## Закрытие issue через PR

В описании PR (или в сообщении связанного коммита) пишем:

```
fixes #12
```

GitHub свяжет этот PR с issue 12; при слиянии PR issue закроется автоматически. Слова-синонимы — closes, resolves. Благодаря этому в истории видно, какое изменение решило какую проблему.

## Взгляд на процесс совместной работы

```
Обнаружен баг → открыт issue (#12) → мейнтейнер вешает label и milestone
  → контрибьютор создаёт ветку и чинит баг → в описании PR: "fixes #12"
  → слияние → issue закрыт автоматически, milestone +1
```

## Практика на реальном GitHub

- Откройте issue в своём репозитории, создайте label и milestone
- Почините баг и отправьте PR, связав его с issue в описании
- Проверьте, закрылся ли issue после слияния автоматически

# Рабочий процесс Pull Request

## Цели урока

- Понять роль PR в совместной работе
- Пройти весь путь: «создать ветку → push → открыть PR → обсудить → слить»
- Узнать три способа слияния и обновление ветки PR

## Что такое pull request

Pull Request (PR) — это официальный запрос «возьмите мои коммиты в ваш репозиторий». У вас нет права писать в чужой репозиторий напрямую, но можно открыть PR — мейнтейнер посмотрит его (review) и решит, сливать ли:

```
Ветка в вашем fork ──push──▶ ваш fork
                               │ открыть PR
                               ▼
                main в репозитории автора (ждёт review и merge)
```

PR — это не только коммиты: в него входят сравнение кода (diff), обсуждение и результаты автопроверок (CI) — это главная единица сотрудничества в open source.

## Открытие PR

Предпосылка: отправить рабочую ветку в свой fork:

```bash
git switch -c fix/login-bug
git commit -am "fix: login bug"
git push origin fix/login-bug
```

Возвращаемся на GitHub: на странице репозитория появится кнопка Compare & pull request. Выбираем base (целевую ветку, например main в репозитории автора) и compare (вашу ветку), пишем заголовок и описание и создаём PR.

## Review и обсуждение

PR — это место для обсуждения: мейнтейнер может комментировать конкретные строки кода (line comments), требовать изменения (request changes) или одобрять (approve). Каждый ваш новый коммит попадает в поток обсуждения; когда всё исправлено, можно @-упомянуть собеседника для повторного ревью.

## Слияние и закрытие

Слияние возможно тремя способами, и история получается разной:

| Способ | История |
| --- | --- |
| Create a merge commit | Сохраняет развилку, создаёт merge-коммит |
| Squash and merge | Сжимает всё в один коммит |
| Rebase and merge | Линейная переигровка, без merge-коммита |

После слияния GitHub обычно предлагает удалить ветку. PR может быть и просто закрыт (closed) без слияния — например, если от идеи отказались.

## Обновление ветки PR

Если мейнтейнер просит правки, новый PR не нужен: продолжаем коммитить в ветку и делать push — PR обновится автоматически:

```bash
git commit -am "fix: address review feedback"
git push origin fix/login-bug
```

## Практика на реальном GitHub

- Отправьте функциональную ветку на GitHub и откройте настоящий PR в репозиторий
- Оставьте комментарий к строке кода в PR и посмотрите, как идёт обсуждение
- Сравните, какую историю дают три способа слияния

# git log и git diff

## Цели урока

- Просматривать историю коммитов с помощью git log
- Просматривать содержимое изменений с помощью git diff
- Просматривать сведения об отдельном коммите с помощью git show
- Прослеживать происхождение строк с помощью git blame
- Познакомиться с коротким хешем и моделью снимков

## git log показывает историю

```bash
git log              # полная история (автор, дата)
git log --oneline    # по одному коммиту в строке: короткий хеш + сообщение
```

SHA-1-хеш каждого коммита — его удостоверение личности. В `git log --oneline` показаны первые 7 символов — короткий хеш; его достаточно, чтобы однозначно указать коммит.

## git diff показывает изменения

```bash
git diff             # working tree vs staging area (изменения без add)
git diff --staged    # staging area vs HEAD (добавленные, но не закоммиченные)
```

Строки, начинающиеся с `-`, — удалённые, а с `+` — добавленные. Перед коммитом проверять через diff, что именно вы изменили, — стандартная привычка.

## git show показывает коммит

```bash
git show <коммит>    # посмотреть сведения о коммите
git show HEAD        # последний коммит
```

`git show` разворачивает коммит: в шапке — хеш, автор, дата и сообщение, ниже — diff относительно родительского коммита. Это прямой ответ на вопрос «что именно изменил этот коммит». Вместе с хешами из git log так можно проследить любое изменение.

## git blame прослеживает происхождение строк

```bash
git blame <файл>   # пометить каждую строку источником
```

blame добавляет к каждой строке файла префикс: **короткий хеш коммита, который последним изменил эту строку, и автор**. Хотите узнать, «кто изменил эту строку и каким коммитом» — blame ответит мгновенно; обычная отправная точка при поиске багов на проде.

## Модель снимков

Каждый commit хранит **полный снимок**, а не разницу. git хеширует содержимое через SHA-1 — одинаковое содержимое даёт одинаковый хеш, поэтому хеш сам по себе проверяет целостность и позволяет избавляться от дубликатов. Именно на этом держится и «распределённость»: история из любого клона полностью восстановима.

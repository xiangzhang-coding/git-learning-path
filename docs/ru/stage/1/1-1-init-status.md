# git init и git status

## Цели урока

- Создать репозиторий с помощью git init
- Разбираться в состоянии репозитория с помощью git status
- Различать tracked и untracked файлы

## git init создаёт репозиторий

Точка старта контроля версий: сказать git «этот каталог — твой».

```bash
git init
```

Он создаёт в текущем каталоге `.git` — внутри лежат база объектов, индекс, ссылки и прочее, и это и есть сам репозиторий. Файлы в рабочей области не затрагиваются: с этого момента каждое их изменение может быть записано.

## git status показывает состояние

`git status` — самая часто используемая команда; она сводит для вас воедино различия между тремя областями:

- на какой вы ветке (On branch ...)
- подготовленные изменения (Changes to be committed)
- неподготовленные изменения (Changes not staged for commit)
- неотслеживаемые файлы (Untracked files)

Запомните одно: **git не отслеживает новые файлы автоматически**. Новый файл нужно сначала `git add` — только тогда он попадёт в staging area и git начнёт следить за ним.

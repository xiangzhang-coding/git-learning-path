# 왜 버전 관리가 필요한가

## 이번 과의 목표

- 버전 관리 시스템(VCS)이 해결하는 문제를 이해한다
- 중앙집중식과 분산식을 비교한다
- Git이 어느 쪽인지 안다

## 버전 관리가 없을 때의 고통

프로젝트를 진행하다가 중간에 방향이 틀렸음을 깨닫고 어제 오후 상태로 돌아가고 싶다면——그 파일은 어디 있을까요? `final_v2_백업` 안에 있을 수도 있고, 이미 덮어써져 사라졌을 수도 있습니다. 협업은 더 심각합니다. 두 사람이 같은 파일을 수정하면 나중에 저장한 사람의 내용만 남고, 다른 사람의 변경은 조용히 사라집니다.

**기록·복귀·협업**——이 세 가지가 Git이 해결하는 문제입니다.

## 버전 관리란

버전 관리 시스템(VCS)은 변경을 기록하고, 각 시점의 프로젝트 전체 **스냅샷**을 저장합니다. 이를 통해 다음이 가능합니다.

- 아무 역사 버전이나 조회
- 두 상태 사이의 차이 비교
- 과거 버전으로 복귀

백업 도구가 아닙니다. 백업은 최신본 하나만 남기지만, VCS는 전체 기록을 보관하며 어떤 버전이든 재구성할 수 있습니다.

## 중앙집중식과 분산식

- **중앙집중식(SVN 등)**: 중앙 저장소가 하나뿐입니다. 모두 그곳에서 체크아웃하고, 커밋은 반드시 서버로 보내야 합니다. 서버가 다운되면 아무도 커밋할 수 없습니다.
- **분산식(Git 등)**: 모든 클론이 중앙 저장소의 완전한 복사본입니다. 커밋은 로컬에서 이루어져 오프라인에서도 작업할 수 있고, 나중에 다른 사람에게 푸시합니다.

Git의 commit은 차이가 아니라 완전한 스냅샷을 저장하므로, 어느 클론에서든 전체 기록을 온전히 재구성할 수 있습니다——이것이 '분산식'이 성립하는 전제입니다.

## 애니메이션: 타임라인 되감기

슬라이더를 움직이거나 점을 클릭하면 버전에 따라 파일 내용이 바뀝니다——'과거로 돌아가기'가 바로 버전 관리가 주는 능력입니다.

# 용어집

용어는 반드시 영어 원문을 유지합니다. 이 표는 한국어 뜻과 처음 등장하는 과를 보여줍니다.

| 용어 | 뜻 | 첫 등장 |
| --- | --- | --- |
| repository | 프로젝트 기록과 메타데이터를 저장하는 디렉터리(`.git` 포함) | 0-2 |
| working tree | 작업 트리. 파일을 편집하는 곳 | 0-2 |
| staging area | 스테이징 영역(일명 index). 다음 커밋에 넣을 변경 목록 | 0-2 |
| commit | 커밋. 완전한 스냅샷의 기록 | 0-1 |
| snapshot | 스냅샷. 어느 시점 프로젝트 전체의 완전한 상태 | 0-1 |
| SHA-1 | 콘텐츠 해시. commit의 고유 식별자 | 단계 1 |
| HEAD | 현재 브랜치의 최신 커밋을 가리키는 포인터 | 단계 2 |
| branch | 브랜치. 이동할 수 있는 커밋 포인터 | 단계 2 |
| tag | 태그. 특정 커밋에 고정된 이름 | 단계 4 |
| remote | 리모트. 다른 곳에 호스팅된 저장소 사본 | 단계 3 |
| origin | 클론 시 기본으로 붙는 리모트 이름 | 단계 3 |
| clone | 클론. 리모트 저장소를 로컬로 복제 | 단계 3 |
| fetch | 페치. 병합 없이 리모트 커밋을 내려받기 | 단계 3 |
| push | 푸시. 로컬 커밋을 리모트로 올리기 | 단계 3 |
| pull | 풀. fetch + merge | 단계 3 |
| merge | 머지. 다른 브랜치를 현재 브랜치에 통합 | 단계 2 |
| rebase | 리베이스. 커밋을 새 기준선에 다시 붙이기 | 단계 4 |
| conflict | 충돌. 겹치는 변경을 수동으로 해결해야 하는 상태 | 단계 2 |
| stash | 스태시. 커밋하지 않은 변경을 잠시 치워 두기 | 단계 4 |
| checkout | 체크아웃. 브랜치 전환 또는 파일 복원 | 단계 2 |
| switch | 스위치. 브랜치 전환(비교적 새로운 명령) | 단계 2 |
| restore | 리스토어. 파일을 특정 버전으로 복원 | 단계 1 |
| reset | 리셋. HEAD와 스테이징 영역/작업 트리 이동 | 단계 4 |
| revert | 리버트. 새 커밋으로 이전 커밋을 취소 | 단계 4 |
| cherry-pick | 체리픽. 특정 커밋을 현재 브랜치에 복사 | 단계 4 |
| diff | 디프. 두 상태 사이의 변경 | 단계 1 |
| status | 상태. 세 영역 사이 차이의 개요 | 단계 1 |
| log | 로그. 커밋 기록 목록 | 단계 1 |
| tracking branch | 추적 브랜치. 리모트 브랜치에 연결된 로컬 브랜치 | 단계 3 |
| upstream | 업스트림. 로컬 브랜치가 추적하는 리모트 브랜치 | 단계 3 |
| fast-forward | 패스트포워드. 분기가 없을 때 앞으로만 이동하는 머지 | 단계 2 |
| detached HEAD | 분리된 HEAD. HEAD가 어떤 브랜치도 가리키지 않음 | 단계 4 |
| reflog | 리플로그. HEAD가 이동한 전체 기록 | 단계 4 |
| DAG | 유향 비순환 그래프. 커밋 기록의 토폴로지 | 단계 2 |
| fork | 포크. 남의 저장소를 내 계정으로 복제 | 단계 5 |
| pull request | 풀 리퀘스트(PR). 브랜치 병합을 요청 | 단계 5 |
| issue | 이슈. 저장소에서 bug/기능/작업을 둘러싼 토론 스레드 | 단계 5 |
| milestone | 마일스톤. issue 무리를 하나의 버전 목표로 묶기 | 단계 5 |
| release | 릴리스. tag를 기반으로 한 정식 버전(설명과 산출물 포함) | 단계 5 |
| workflow | 워크플로. GitHub Actions의 자동화 절차 | 단계 5 |

# なぜバージョン管理が必要か

## この課の目標

- バージョン管理システム（VCS）が解決する問題を理解する
- 集中型と分散型を比較する
- Git がどちらかを知る

## バージョン管理がないと何が起こるか

プロジェクトを進めていて、途中で方針がダメだと気づき、昨日の午後の状態に戻りたい——そのファイルはどこにありますか？`final_v2_バックアップ` の中か、あるいはもう上書きされて消えているかもしれません。共同作業はさらに深刻です。2 人が同じファイルを編集し、後から保存した人の内容だけが残り、もう 1 人の変更は静かに消えます。

**記録・巻き戻し・共同作業**——この 3 つが Git が解決する問題です。

## バージョン管理とは

バージョン管理システム（VCS）は変更を記録し、各時点のプロジェクトの完全な**スナップショット**を保存します。これにより次のことができます。

- 任意の履歴バージョンを表示する
- 任意の 2 つの状態の差分を比べる
- 過去の任意のバージョンに巻き戻す

バックアップツールではありません。バックアップは最新 1 件だけを残しますが、VCS は履歴全体を保持し、どのバージョンも再構築できます。

## 集中型と分散型

- **集中型（SVN など）**：中央リポジトリが 1 つだけ。全員がそこからチェックアウトし、コミットは必ずサーバーへの送信が必要。サーバーが落ちると誰もコミットできません。
- **分散型（Git など）**：各クローンが中央リポジトリの完全なコピー。コミットはローカルで行われ、オフラインでも作業できます。後で他人にプッシュします。

Git の commit は差分ではなく完全なスナップショットを保存するため、どのクローンからでも履歴全体を完全に再構築できます——これこそ「分散型」が成立する前提です。

## アニメーション：タイムラインを巻き戻す

スライダーを動かすか丸をクリックすると、バージョンごとのファイル内容が変わります——「過去に戻る」ことがバージョン管理の力です。
